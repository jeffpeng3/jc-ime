# 變更記錄

這裡只記使用者看得到的變更。版本號對應 `Cargo.toml` 的
`[workspace.package] version`；release workflow 會抓 `## <version>` 段落放進
GitHub Release。較舊的版本留在 git 歷史，`git log -- docs/CHANGELOG.md` 可回溯。

## 未發布

### 修正

- 升級後不必登出登入：安裝器先用 `jc-engine --stop` 要求舊引擎收尾，
  新版引擎再比對版本與 SHA-256 接手；`[Run]` 最後用
  `jc-engine --verify-running` 確認跑的是剛安裝的 binary。
- 舊引擎無法優雅停止時，先送 `Shutdown` 讓個人學習資料存檔，才強制結束行程。
- 安裝器的引擎行程確認改成 fail-closed：PowerShell 不可用時改用 `tasklist`，
  兩者都無法確認就不覆蓋檔案。
- `jc-engine --verify-running` 在接手期間看到舊身分會等到期限，不再提早失敗。
- `--stop` 即使單例鎖是空的，也會探 socket 清掉沒有 supervisor 的 orphan 引擎。
- 反安裝同樣先 `--stop`，再移除檔案與註冊；提權身分對不到原使用者時仍以
  `taskkill` 收尾，最後一次 flush 可能沒有。
- 引擎行程確認與強制結束改為只處理目前 session；取不到 session 才退回
  machine-wide 並寫 log。
- 停止要求檔以 60 秒判定殘骸：崩潰的 `--stop` 可能讓 60 秒內的引擎啟動
  直接退出，取捨已寫在文件。
- 身分檔寫入失敗時先探 socket；有回應就等完整 `shutdown_grace`，不提早
  強制結束。

## 0.1.32 - 2026-11-28

### 修正

- Caps Lock 開著時注音鍵不再失效：`su3cl3` → 你好、`w96j0` → 台灣。
- 組字中切英文不再取消或送出組字；英文輸入以字面追加，與 Shift+A 相同。
- `Ctrl+Alt+,`／`Ctrl+Alt+.` 改用全域快捷鍵，符號與表情選單現在能在任何程式
  開啟，也不再觸發應用程式自己的同名快捷鍵。
- 英文 Tab 候選只留目前字面與正確補全，移除逐字分解；開窗時高亮第一項。
- 候選窗改用「顯示字元」為目標：游標在中間時只處理該字元，不再重解整段。
  例如 `ㄨㄛ|ˇ` 只對 `ˇ`、`わた|し` 只對 `し`、`ji3|` 只對 `3`。
- 日文 decoder lane 的 `↓` 也走同一條顯示字元路徑；`わた|し` 只列 `し` 與
  `shi`，不再列出整個文節。候選只由 target unit 的 keys 產生。
- 日文刪除一次只刪一個顯示字元；`kyo` 退一個字元是 `き`。

### 內部

- 新增顯示字元 provenance（`DisplayUnit`：surface、keys、reading、meta）。
- 整理文件：刪除 159 個過時調查與一次性紀錄，合併重複主題。
- 新增 crate 切分與命名 review 報告。

## 0.1.31 - 2026-11-28

### 新增

- 前導字元 `u`／`b`：`` `u 4e00 `` 加空白插入「一」，`` `b a440 `` 加空白也插入
  「一」（Unicode／Big5 碼位查詢）。
- 混合模式的英文補全改用候選窗：打 `hellp` 按 Tab 開窗，選 `hello`；方向鍵、
  數字鍵、Enter 與其他候選一致。

### 變更

- 英文模式改成純 raw：文字鍵直接交給應用程式，不經引擎；已註冊的選單快捷鍵
  （Ctrl+Alt+,／.）仍然可用。
- 移除 `caps_letter` 設定，Caps Lock 一律照系統行為。

### 修正

- 重播連線記錄時不再重複寫入學習統計。

### 內部

- 新增語言引擎介面（`LanguageEngine` trait、Fast path、前導控制引擎）。
- Big5 → Unicode 查表與產生腳本。
- 移除 `jc-ui`、`Request::Context`／`Mode`／`CapsLock` 等死路徑。

## 0.1.30 - 2026-11-27

### 變更

- 刪除鍵所有語言統一：`Delete` 刪游標右邊一個可見字元，`Backspace` 刪左邊
  一個。不再按注音音節、日文文節或羅馬字群組刪除。
- 日文刪除後保留剩下的字面，即時轉換不會再改寫其他字；一個漢字對應多個
  讀音時，整段讀音一起刪除。

### 修正

- 英文字面刪除後，剩下的字母不會再被重判成注音或かな。

## 0.1.29 - 2026-11-27

### 修正

- Caps Lock 只改英文字母的大小寫，不再讓注音鍵失效：Caps Lock 開著時
  `w96j0` 仍是「台灣」。
- 選了原始輸入後游標停在字面尾端，Backspace 可以刪；再按 `↓` 仍給整個音節的
  完整候選。
- 候選清單在每次變換後都保留完整選項：選かな拆解、刪聲調之後不再只剩自己。
- 日文選字不再疊字；游標停在片段時按 `↓` 可以選該段的 し 與原始 `shi`。
- 四欄候選窗在最右欄按 `→` 會換到下一頁第 1 欄，`←` 對稱回上一頁。
- 符號與表情選單現在會顯示分頁列，`Tab`／`Shift+Tab` 換頁。
- 登入自動啟動不再留下終端機視窗。

### 新增

- 日文 `F6`–`F10`／`Convert`／`NonConvert` 現在真的到得了轉換層。

### 內部

- 候選套用、按鍵政策、候選組裝、游標、TSF 模式、顯示與提交各自收成單一路徑。
- 移除 legacy 日文模式、`Request::Toggle`、`candidate_kind` 等死路徑。

## 0.1.28 - 2026-11-27

### 新增

- 候選清單固定順序：第 1 項是目前值、第 2 項是原始輸入（`ji3`、`ㄨㄛˇ`、
  `su`）、第 3 項起才是推薦排序。誤判成英文或其他語言時，可以直接選回原始輸入。
- 日文候選也能選回原始羅馬字：轉成カナ（`ス`）後仍可退回 `su`。
- 候選上限提高到 200（量測顯示單鍵僅增加 0.1ms）；四欄一頁可填滿 40 項。
- 設定程式的快捷鍵欄位可以「錄製」：按下按鈕後直接按組合鍵，不需要手打；
  錄製期間切換分頁會自動取消。
- 安裝精靈新增「安裝後執行診斷」選項，預設不執行。

### 修正

- 直向候選窗按 `↓` 到底會換到下一頁，不再看起來像在同一欄循環。
- 開著 Caps Lock 時英文字母一律大寫字面，不再被打成注音（反轉 #168 的舊行為）。
- 日文逐鍵預覽不再遺失未完成的羅馬字：先前要打完才會看到轉換結果。

### 資料與模型

- 日文神經模型由 Jinen v2 small Q5_K_M 換成 Q4_K_M：轉換中位數快 25%、
  每句 CPU 少 31%、引擎記憶體少 17MB、`setup.exe` 少 9.4MB，品質持平。
- 新增三份調查報告：候選上限對延遲的影響、語言與模式分岔盤點、Zenz v2.5
  medium 的可行性與品質對照（結論：目前不換）。

## 0.1.27 - 2026-11-26

### 新增

- 候選窗改成語言無關的通用清單：預設 10 列，按 `←`／`→` 展開成 4 欄；
  `↑`／`↓` 移動一項、`←`／`→` 跳一整欄；數字 `1`–`0` 選目前那一欄的列。
  英文候選現在也有數字編號。
- 日文輸入每鍵都有部分預覽，停頓只補完最後一個文節；已轉出的漢字不會退回
  平假名，畫面不再抽動。
- 設定程式的快捷鍵欄位加上 chord 語法說明、欄位錯誤提示與「重設為預設」。

### 修正

- 候選窗第一項與組字區顯示的字一致；個人學習排序不再造成「顯示我、第一項是捰」。
- 候選窗按 Enter 只套用高亮候選、保留組字；前導符號這類「高亮項就是目前字面」
  的情況仍是一次送出。
- 連續多個前導符號（`` ` ; `` `` ` [ ``）提交後不再只剩最後一個。
- 日文 `↓` 不再移動游標，列出整段候選，包含原始羅馬字與全形／半形カナ。
- 英文模式組字中的 Enter／Backspace／Esc／Tab 比照注音規則；Tab 沒有補全時不動作。
- 組字中按 Shift 不再探測引擎、不再誤報引擎掛掉；Shift＋字母留在組字。
- 沒有 Shift 的大寫字母（Caps Lock）一律當字面，不再被打成注音。
- 套用「原始按鍵」這類字面候選時，前面的注音不會退回原始按鍵。
- 長英文 run 後面接注音時，已轉換的漢字不會退回；45 字母的長英文詞維持完整字面。
- 注音鏈出現在長 run 尾巴時不會退化。
- 設定程式第一次開啟不再全部空白。

### 建置

- Linux CI gate 改用 `cargo nextest`，doctest 另外跑；同一台機器從 551 秒降到
  87 秒，CI 的 Linux job 約 3 分鐘。
- 新增每週 `test-compat` job：用傳統 `cargo test` 與 nextest 比對，兩邊分叉就紅。
- clippy／check 走 mbx 共用編譯快取（開發機）：暖命中約 1.7 秒，多個 worktree
  共用同一份產物。
- 新增 `scripts/test-plan.sh`（內圈只跑受影響的 crate／模組）、`scripts/check.sh`
  與 `scripts/mbx-gc.sh`。
- doctor 檢查 5 不再重複激活 TIP，修正實機 `E_INVALIDARG` 誤判。
- 新增開發依賴（`gpui-kit` test-support）後重新產生 Rust 授權清單。

## 0.1.26 - 2026-11-26

### 修正

- 候選窗第一項現在與組字區顯示的字一致；有個人學習排序時不再出現「顯示我、
  第一項是捰」。
- 候選窗按 Enter 只套用高亮候選、關窗、保留組字，再按一次 Enter 才送出整段。
- 日文輸入停頓後會自動轉換（`watashiwa` → 私は）；`↓` 不再移動游標，列出整段
  候選，包含原始羅馬字、全形與半形カナ。
- 組字剩最後一個字元時按 Backspace／Delete 不再多刪一個已送出的字；符號或
  表情選單開著時也一樣。
- 組字中按 Shift 不再探測引擎、不再誤報引擎掛掉；Shift＋字母留在組字
  （`台ㄨㄢ` + Shift+A 是 `台ㄨㄢA`）。
- Shift＋符號不再讓按鍵處理 panic；反引號前導表可以接受 Shift 產生的大括號等符號。
- 連續多個前導符號（`` ` ; `` `` ` [ ``）提交後不再只剩最後一個。
- 套用「原始按鍵」這類字面候選時，前面的注音不會退回原始按鍵。
- 設定程式第一次開啟不再全部空白；缺值的欄位回到平台預設。
- 長串英數混標點的輸入不再每鍵變慢（180 字元時 25–30ms 降到微秒級），也不會
  再冒出注音字元。
- 45 字母的長英文詞維持完整字面，不再被切成かな。
- 長英文 run 後面接注音時，已轉換的漢字不會退回原始按鍵。

### 建置

- release 建置開啟 `strip`、thin LTO 與 `panic = "abort"`；兩支 TSF DLL 維持
  unwind，`catch_unwind` 仍然有效（避免 panic 拖垮宿主程式）。Windows 七支
  二進位合計 57.0 → 43.0 MiB。
- doctor 檢查 5 不再重複激活 TIP，修正實機誤判 `E_INVALIDARG`。
- 新增 `scripts/ja-size/`：日文資料體積分析。
